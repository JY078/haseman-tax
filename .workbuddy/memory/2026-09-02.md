## Smart Suite 生图 prompt 审查

审查链路：`lock-suite-style` → `direct-suite-creative` / `direct-secondary-suite` → `plan-suite-image`
→ `ecom_suite.go:buildSmartSuiteImageGenerationPromptForTask`（组装最终 JSON contract）。

### 发现的真实缺陷（待修）
1. `ecom_suite.go:smartSuiteGenerationTypographyInstruction` 的三条正则会删掉 `700 weight`、
   `500 weight` 这类数字字重，导致 font_system 语义残缺（"use for short benefit headlines"）。
2. `ecom_suite.go:sanitizeSmartSuiteTechnicalMetadata` 只做空白归一化，不清理标点残留；
   删除 "UI card" 后留下 `slideshow, , brochure` 双逗号。
3. `people_rule` 引用 `visual_evidence`，实际字段名为 `scene_evidence`，字段名不自洽。
4. `negative_constraints` 硬编码 "exactly two visible text items"，与 "both non-empty copy_items"
   在文案为空时冲突。
5. `layout_instruction` 一边列出百分比坐标一边禁止渲染百分比；坐标应只由 `layout_spec.text_safe_area` 承载。

### 主要冗余
`image_plan.scene` 把整套 `suite_style` 九字段复述一遍；`typography_instruction` 出现 3 次；
`product_lock` 出现 2 次；`image_goal` / `persuasion_task` / `confirmed_fact` 三处重复同一事实。

### 产品摆位（placement）推理方案
用户提出：需要根据产品图判断产品适合放在哪里（厨房水龙头可放岛台也可放池台）。
方案：analyze-product-facts 增 `placement_options` → lock-suite-style 的 background_tone 不再写死
"installed at the sink"（当前这句锁死了摆位）→ creative direction 按图分配 placement →
contract 增 `image_plan.placement`。事实边界：placement 是场景选择，未获文档确认时不能变成兼容性 claim。

状态：仅分析，未改代码，等用户确认后再落地。
