## 修复亚马逊价格抓取（订单汇总页）

**文件**：`backend/internal/handler/product_price_html.go`（重写解析流程）、`backend/internal/handler/product_price_fetch_test.go`（+2 回归测试）

**问题**：Firecrawl 抓取 amazon.com/dp/{ASIN} 成功返回 HTML，但解析器一律报「主商品 HTML 中没有可确认的美元售价」。

**根因**（亚马逊 2026 年新版页面结构）：
1. 同一 buybox 内新品行与二手行是同级 accordion，各自带独立价格块：
   `newAccordionRow_0` / `apex_desktop_newAccordionRow` 与 `usedAccordionRow` / `apex_desktop_usedAccordionRow`。
   原代码把所有价格区合并统计，新品价与二手价同时进候选集，`len(currents)==1` 恒不成立。
2. `apex_desktop`、`desktop_unifiedPrice` 是外层容器，内部还嵌套 `corePriceDisplay_desktop_feature_div`，
   原代码把外层容器也当独立区域，进一步放大污染。
3. 兜底的全局扫描会收进 twister 变体 swatch 价（`div#apex_price.apex_on_twister_price`、
   `dimension-slot-info-*`），那是其它颜色/尺码的价格。

**修复**：
- 新增 `amazonPriceRegionID()` 统一区域 ID 判定。
- 新增 `amazonInnermostPriceRegions()`：丢弃内含其它区域的外层容器。
- 新增 `amazonAccordionRowKind()`：按祖先 id 是否含 `newaccordionrow` / `usedaccordionrow` 分类
  （注意 id 是 `newAccordionRow_0` 这种带后缀的，必须用 Contains 而非等值比较）。
- 新增 `amazonHTMLScanner` 结构体 + `regionPrices(scope)`，按 NEW → 非USED → 全部 三级作用域依次尝试。
- 新增 `amazonPriceResult()` 收敛原价/折扣价构造。
- 兜底扫描排除 `usedaccordionrow`、`apex_price`、`apex_on_twister_price`、`dimension-slot-info`。

**验证**：用真实 Firecrawl key 抓取后，`fetchAmazonPrice` 端到端输出
B0DWK6K6L5 → 原价 $55.99 / 折扣价 $49.78；B0G7H6Q7BZ → 原价 $66.99 / 无折扣。
handler 包全量测试通过（含原有 13 个亚马逊 HTML 价格用例）。

**注意**：Firecrawl `formats: ["html"]` + `onlyMainContent: true` 时返回的是 `data.html`（`rawHtml` 为空），
且页面里没有 `input#ASIN`，只能靠 `data-csa-c-asin` 判定 ASIN 归属。

**待办**：用户给的 Firecrawl key 未写入后台设置（`firecrawl_api_key`），需用户确认后再配。

## 修复 Firecrawl 429 / 响应超时（同日，接上）

**文件**：`backend/internal/handler/product_price_fetch.go`、`product_price_fetch_test.go`、
`web/src/views/ProductPricesView.vue`

**Firecrawl 限速事实（docs.firecrawl.dev/rate-limits）**：
- `/scrape` 每分钟上限：Free 10、Hobby 100、Standard 500，**按团队计**（同一团队所有 key 共享计数）。
- 并发浏览器上限：Free 2、Hobby 5、Standard 25，超限同样返回 429。
- **排队等浏览器的时间会计入请求里的 `timeout` 参数**，`timeout` 最大只能到 60000ms。
- ⇒ 超时类失败的根因：任务排队把 30s 的 timeout 烧光了。

**原代码三个问题**：
1. `timeout: 30000` 太紧，且客户端 `Timeout = 40s`（实测单次抓取 8~34s，贴着上限）→「读取 Firecrawl 响应失败或超时」。
2. 429/5xx/网络错误完全不重试；前端虽写了 429 重试，但后端把 429 统一转成 502 返回，那段是死代码。
3. 无任何并发控制，前端 2 个 worker + 多用户 + Home Depot 抓取共用同一团队配额。

**修复**：
- 新增常量：`amazonPriceAttemptTimeout=70s`、`amazonPriceFetchBudget=150s`、
  `amazonPriceFetchAttempts=3`、`amazonPriceRetryMax=20s`、`amazonPriceScrapeTimeoutMS=60000`、
  `amazonPriceScrapeParallel=2`。
- `amazonPriceScrapeSlots` 缓冲 channel 做全局并发闸门（2），排队超时走 `amazonPriceQueueError`。
- `fetchAmazonPrice` 拆成「重试循环 + `fetchAmazonPriceOnce`」；`amazonRetryableError`（内嵌 error + `Unwrap`
  + `wait`）标记可重试；`amazonRetryAfter` 解析 `Retry-After`（秒数/HTTP date）。
- 可重试：429、5xx、传输错误、响应解码失败（空/截断/格式异常）。
  不可重试：401/403/402，以及 `errAmazonPriceNotFound`（页面没价格，重试无意义且费额度）。
- 429 用 sentinel `errAmazonFirecrawlRateLimited`，handler 返回**真正的 429** 而不是 502。
- 前端：`timeout: 45000` → `170000`，删掉那段失效的 429 重试循环（退避交给后端）。

**测试**：`amazonPriceRetryBase` 是 var（测试里 init 改为 10ms）；新增 5 个用例覆盖重试次数、
Retry-After 恢复、限流错误可识别、无价格页面不重试、超时常量关系。handler 包全量通过。

**注意**：Home Depot  listing 抓取（`home_depot_listing_fetch.go`）走同一个团队配额（一次最多 3 次 scrape），
会和价格批量抓取互相挤占，必要时也要加同样的闸门。

## 无货 ASIN 不再误抓推荐位价格（同日，接上）

**文件**：`backend/internal/handler/product_price_html.go`、`product_price_fetch.go`（+测试）

**现象**：`B0B4G46RC3` 无货，却把上方「Consider these available items」推荐卡的价格填进去。

**页面实况**（Firecrawl 抓下来的 HTML）：
- 买box 完全空：`desktop_unifiedPrice` / `unifiedPrice_feature_div` / `apex_desktop` 三个区域的文本都是空串。
- 页面里全部 21 个 `$` 价格只来自三处：
  1. `div._Y2VyY_afFixedGridContentWithAtcBtn_3p` + `cerberusSharedCards-widgetTypeOos` —— 就是「Consider these available items」无货推荐卡；
  2. `div.p13n-asin` / `sp_detail_*` 推荐轮播；
  3. `div.apm-tablemodule` A+ 对比表。
- 页面明确有 `<div id="availability">Currently unavailable. We don't know when or if this item will be back in stock.</div>`，
  同款文本还出现在 `#outOfStock`、`#availability_feature_div`。

**修复**：
- 新增 `isAmazonAvailabilityID()`（只认 `availability` / `availability_feature_div` / `outOfStock`）
  与 `amazonAvailabilitySaysUnavailable()`（短语：currently unavailable / out of stock / no longer available）。
- 在 `amazonHTMLPrice` 里 **`unavailableOffer` 的判断放在区域扫描之后、aod 与全局兜底扫描之前**：
  即"先试着找真价格，找不到且页面说无货 → 返回 `errAmazonPriceUnavailable`"，
  **绝不回退到推荐位**。这样变体页里"某个子 ASIN 无货但主买box 有价"的情况不会被误判。
- 全局兜底扫描的排除词新增 `cerberus`、`atcbtn`（对应无货推荐卡的 class）。
- `parseAmazonFirecrawlResponse` 之前会把 `amazonHTMLPrice` 的错误一律替换成 `errAmazonPriceNotFound`，
  把"无货"这个具体原因吞掉了；改为 `amazonPriceErrorIsTerminal(err)` 时原样透传。
- `errAmazonPriceUnavailable` 归入 terminal，**不重试**（重试只会多烧额度）。

**回归**：B0DWK6K6L5 → 55.99/49.78、B0G7H6Q7BZ → 66.99、B0B4G46RC3 → 无货，真实端到端全部正确。

**坑**：`amazonHTMLPrice` 内部大部分失败返回的是局部变量 `invalid`（"主商品 HTML 中没有可确认的美元售价"），
不是 `errAmazonPriceNotFound`——后者只在 `parseAmazonFirecrawlResponse` 里产生。写测试断言时要分清。
