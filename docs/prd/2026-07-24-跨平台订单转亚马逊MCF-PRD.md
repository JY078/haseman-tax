# 跨平台订单转亚马逊 MCF 工具 PRD

| 项目 | 内容 |
| --- | --- |
| 文档版本 | V1.0 |
| 文档状态 | 待评审 |
| 编写日期 | 2026-07-24 |
| 产品名称 | 订单转 MCF |
| 适用平台 | TEMU、TikTok Shop（下文简称 TikTok） |
| 目标用户 | TEMU/TikTok 平台运营、Amazon MCF 履约人员、系统管理员 |

## 1. 需求概述

在现有内部工作台的“工具”中新增“订单转 MCF”工具。用户上传 TEMU 或 TikTok 的订单导出文件，系统根据已维护的“平台 SKU → Amazon Merchant SKU”映射，将订单字段转换为 Amazon MCF 模板，并下载可直接用于 Amazon MCF 批量导入的 TXT 文件。

首版重点解决两件事：

1. 将两种来源不同、字段不同的订单文件稳定转换成同一份 Amazon MCF 模板。
2. 让对应平台的运营人员维护本平台 SKU 与 Amazon SKU 的映射，并在以后导入时自动复用。

## 2. 背景与问题

当前系统主要集中在生图能力，内部运营类工具不足。跨平台订单转 Amazon MCF 依赖人工复制订单、地址和 SKU，存在以下问题：

- TEMU、TikTok 与 Amazon 使用的 SKU 不一致，无法直接导入。
- 两个平台的订单字段名称、时间格式、地址格式和文件格式不同。
- 人工复制容易出现 SKU、数量、邮编、电话或地址错误，错误往往到履约阶段才暴露。
- SKU 对应关系没有统一沉淀，同一 SKU 会被反复确认。
- 订单包含姓名、电话和地址，不适合在无必要时长期保存到系统或日志。

服务器为 4 核、7.5 GB 内存，已观察到的峰值占用约 3.1 GB，现有余量足以支持该工具。但首版不应为了消耗余量引入重型服务；文件转换属于轻量表格处理。

## 3. 产品目标

### 3.1 目标

- 支持上传并识别 TEMU `.xlsx` 和 TikTok `.csv` 订单文件。
- 按 Amazon MCF 模板固定的 24 个字段生成 TXT 文件。
- 支持平台 SKU 映射的查询、新增、修改、停用和复用。
- 在下载前集中暴露未映射 SKU、缺失收件信息、无效数量等问题。
- 默认不持久化源订单、转换结果或收件人个人信息。
- 10,000 条订单明细的常规转换在 5 秒内完成（不含用户人工匹配时间）。

### 3.2 非目标

首版不包含：

- 直接调用 Amazon MCF API 创建订单。
- 自动登录 TEMU、TikTok 或 Amazon 拉取订单。
- 库存校验、运费试算、物流跟踪和取消 MCF 订单。
- AI 猜测 SKU、模糊自动匹配 SKU 或根据商品名称自动决定 Amazon SKU。
- 通用的任意表格字段映射器。
- 保存或提供历史订单文件下载。
- TEMU/TikTok 以外的平台。

## 4. 核心假设与待确认项

以下假设用于形成首版方案，评审时需要业务确认：

| 编号 | 假设/待确认项 | 当前建议 |
| --- | --- | --- |
| A1 | 现有系统 `product_skus.SKU` 是否就是 Amazon 可履约的 MerchantSKU | 若是，作为映射目标主数据；若不是，需要独立的 Amazon SKU 主数据，不能直接复用现有 SKU 库 |
| A2 | MCF 订单号是否需要平台前缀 | 建议使用 `TEMU-`、`TK-` 前缀，避免跨平台订单号碰撞，并便于 Amazon 后台识别来源 |
| A3 | 默认配送等级 | 按现有模板固定为 `Standard`，后续如有加急需求再增加选择 |
| A4 | 订单备注 | 按现有模板固定为 `Thank you for choosing FORIOUS. We hope you enjoy your purchase!` |
| A5 | 可导出订单状态 | TEMU 仅导出“待发货”；TikTok 仅导出“待发货”且 `Fulfillment Type = Fulfillment by seller` 的明细 |
| A6 | Amazon MCF 模板版本 | 首版以本次提供的 24 列模板为唯一输出版本；Amazon 模板变更后需同步更新规则和回归样例 |
| A7 | 文件规模 | 首版单文件不超过 10 MB、20,000 条明细；超过时阻断并提示拆分文件 |

## 5. 用户与权限

| 用户 | 能力 |
| --- | --- |
| 已登录用户 | 上传文件、查看转换预览、使用已有映射、下载 MCF 文件 |
| 平台运营 | 拥有已登录用户能力；可新增和修改自己所属平台的 SKU 映射 |
| 系统管理员 | 可查看、修改、停用所有平台映射，处理错误映射 |

权限建议复用用户现有的 `Platform` 字段：TEMU 用户只能维护 TEMU 映射，TikTok 用户只能维护 TikTok 映射；管理员不受平台限制。读取映射和转换文件不应要求管理员权限。

## 6. 使用入口与页面流程

### 6.1 入口

- 一级入口：现有顶部导航“工具”。
- 二级入口：“订单转 MCF”。
- 页面路由建议：`/order-to-mcf`。
- 该功能需登录后使用。

### 6.2 主流程

1. 用户进入“订单转 MCF”。
2. 用户选择来源平台，或直接上传文件由系统识别平台。
3. 系统在浏览器本地解析文件，展示文件名、平台、订单数、明细数和可导出数。
4. 系统提取当前文件中去重后的平台 SKU，并查询已有映射。
5. 若存在未映射 SKU，用户必须逐项选择或输入 Amazon SKU；保存后可被后续订单复用。
6. 系统生成转换预览，按“可导出、警告、阻断”展示每条明细状态。
7. 用户修正可编辑字段或 SKU 映射，直到不存在阻断项。
8. 用户点击“生成 MCF 文件”，浏览器下载 TXT 文件。
9. 页面显示本次导出汇总，不保存订单明细。

流程原则：上传文件后不直接下载，必须经过“SKU 映射完整性 + 订单字段校验”两道检查。

## 7. 页面需求

### 7.1 文件上传区

- 支持拖拽或选择文件。
- TEMU：仅接受 `.xlsx`。
- TikTok：仅接受 `.csv`。
- 显示支持格式和 10 MB 大小上限。
- 文件上传后显示自动识别的平台；识别结果与用户选择不一致时阻断。
- 支持移除文件并重新上传；一次只处理一个来源文件，避免不同平台规则混用。

### 7.2 导入汇总区

至少显示：

- 来源平台。
- 源文件名。
- 原始明细数。
- 可导出明细数。
- 因状态或履约方式被排除的明细数。
- SKU 总数、已映射 SKU 数、未映射 SKU 数。
- 阻断错误数、警告数。

### 7.3 SKU 映射区

每个去重后的平台 SKU 显示：

- 平台。
- 平台 SKU。
- 源商品名称/规格（只用于帮助人工判断，不作为匹配依据）。
- 当前 Amazon SKU。
- 映射状态：已映射、未映射、已停用。
- 影响的订单明细数和商品数量合计。
- 操作：选择 Amazon SKU、修改、保存。

交互要求：

- Amazon SKU 输入框支持按 SKU、商品名、SPU 搜索现有 SKU 主数据。
- 不做自动模糊匹配，不因名称相似自动保存映射。
- 同一平台 SKU 只能存在一个生效映射；不同平台 SKU 可以映射到同一个 Amazon SKU。
- 修改已有映射时明确提示“会影响以后上传的订单”，并记录修改人和修改时间。
- 当目标 Amazon SKU 不在主数据中时，首版是否允许手工输入取决于 A1：若现有 SKU 库是权威主数据，则禁止；否则允许输入但标记“未校验”。

### 7.4 转换预览区

按订单明细展示以下高价值字段：

- 状态。
- 来源订单号。
- 平台 SKU。
- Amazon SKU。
- 数量。
- 收件人。
- 城市、州、邮编、国家。
- 手机号。
- 错误/警告原因。

支持筛选“全部、阻断、警告、可导出”。阻断项必须从导出中排除；用户也可以主动取消勾选某条可导出明细。为避免误发，同一订单只要有一条待导出明细存在阻断，整个订单默认不允许导出。

首版允许在预览中修正收件信息和数量；只有对应平台运营或管理员可以修改 Amazon SKU 映射。修正不回写源文件；刷新页面或移除文件后，订单字段修正不保留，SKU 映射除外。

### 7.5 下载区

- 主按钮：“生成 MCF 文件”。
- 存在阻断项时按钮禁用，并显示剩余问题数量。
- 下载文件名：`MCF_{TEMU或TK}_{yyyyMMdd_HHmmss}.txt`。
- 下载后显示导出订单数、明细数、商品总件数和被排除数。

## 8. 文件识别与清洗规则

### 8.1 TEMU 文件识别

同时包含以下表头时识别为 TEMU：

`订单号`、`应履约件数`、`SKU货号`、`收货人姓名`、`详细地址1`、`城市`、`省份`、`收货地址邮编`、`国家`。

### 8.2 TikTok 文件识别

同时包含以下表头时识别为 TikTok：

`Order ID`、`Order Status`、`Seller SKU`、`Quantity`、`Recipient`、`Phone #`、`Country`、`State`、`City`、`Zipcode`、`Address Line 1`。

### 8.3 通用清洗

- 所有订单号、SKU、邮编按文本处理，禁止转为科学计数法或丢失前导零。
- 去除字段首尾空格、尾随制表符和不可见控制字符。
- 单元格内换行和制表符在输出前替换为空格，避免破坏 MCF 行列结构。
- `--`、连续星号遮罩、空白字符串视为空值。
- 数量转换为正整数；小数、非数字、零和负数均阻断。
- 日期按来源格式解析并输出为 `YYYY-MM-DDTHH:mm:ss`，不擅自改变源时区。
- 国家统一转换为 ISO 3166-1 两位代码；首版只允许美国地址，输出 `US`。
- 美国州名（含中文州名、英文全称）转换为两位州代码；无法识别时阻断并允许人工修正。
- 电话保留可识别的国家码和数字；清洗后位数明显不足时阻断。

### 8.4 TikTok 特殊规则

- `Quantity for MCF = Quantity - Sku Quantity of return`；结果小于等于 0 时排除。
- 仅处理 `Fulfillment by seller` 的待发货订单，平台仓履约订单不重复发送至 MCF。
- `Phone #` 为主来源。若位数不足，但 `Shipping Information` 中能无歧义提取到更完整的同一收件人电话，可将其作为建议值展示，必须由用户确认后才能导出。
- TikTok CSV 按本次样例的 GB18030/ANSI 中文编码兼容读取，同时兼容带 BOM 的 UTF-8；解码失败或出现替换字符时阻断，禁止带乱码导出。

### 8.5 TEMU 特殊规则

- 使用 `应履约件数` 作为 MCF 数量。
- 使用 `SKU货号` 作为平台 SKU，不使用 `SKUID`、`SKCID` 或 `SPUID` 做映射。
- 当前样例中的姓名、电话和地址为星号遮罩。实际上传文件若仍为遮罩信息，整单阻断并提示用户从平台导出包含完整收件信息的订单文件。

## 9. Amazon MCF 字段映射

输出字段顺序必须与模板完全一致，不允许增删、改名或换序。

| # | Amazon MCF 字段 | TEMU 来源/规则 | TikTok 来源/规则 |
| --- | --- | --- | --- |
| 1 | MerchantFulfillmentOrderID | `TEMU-{订单号}` | `TK-{清洗后的 Order ID}`；已有 `TK-` 时不重复添加 |
| 2 | DisplayableOrderID | 同 MerchantFulfillmentOrderID | 同 MerchantFulfillmentOrderID |
| 3 | DisplayableOrderDate | `订单创建时间` 转 ISO 格式 | `Created Time` 转 ISO 格式 |
| 4 | MerchantSKU | `SKU货号` 查询平台 SKU 映射 | `Seller SKU` 查询平台 SKU 映射 |
| 5 | Quantity | `应履约件数` | `Quantity - Sku Quantity of return` |
| 6 | MerchantFulfillmentOrderItemID | 与 `MerchantSKU` 相同，填写映射后的 Amazon SKU | 与 `MerchantSKU` 相同，填写映射后的 Amazon SKU |
| 7 | GiftMessage | 空 | 空 |
| 8 | DisplayableComment | 空 | 空 |
| 9 | PerUnitDeclaredValue | 空 | 空 |
| 10 | DisplayableOrderComment | 固定订单备注（见 A4） | 固定订单备注（见 A4） |
| 11 | DeliverySLA | `Standard` | `Standard` |
| 12 | AddressName | `收货人姓名` | `Recipient` |
| 13 | AddressFieldOne | `详细地址1` | `Address Line 1` |
| 14 | AddressFieldTwo | `详细地址2`，无值留空 | `Address Line 2`，无值留空 |
| 15 | AddressFieldThree | `详细地址3` 与有效的 `区县` 以空格拼接 | 空 |
| 16 | AddressCity | `城市` | `City` |
| 17 | AddressCountryCode | `国家` 标准化，首版仅输出 `US` | `Country` 标准化，首版仅输出 `US` |
| 18 | AddressStateOrRegion | `省份` 标准化为两位州代码 | `State` 标准化为两位州代码 |
| 19 | AddressPostalCode | `收货地址邮编`，按文本保留 | `Zipcode`，按文本保留 |
| 20 | AddressPhoneNumber | `收货人联系方式` | `Phone #`，不足时按 8.4 提示确认 |
| 21 | NotificationEmail | `邮箱`，无值留空 | 空 |
| 22 | FulfillmentAction | 空 | 空 |
| 23 | MarketplaceID | 空 | 空 |
| 24 | CarrierPreferences | 空 | 空 |

### 9.1 多明细订单规则

- 同一来源订单的所有明细使用相同的 `MerchantFulfillmentOrderID`。
- `MerchantFulfillmentOrderItemID` 与 `MerchantSKU` 填写相同的 Amazon SKU。
- 同一订单中多个源明细最终映射到相同 Amazon SKU 时，合并为一条 MCF 明细并汇总 `Quantity`，避免商品项 ID 重复。
- 同一订单任一明细被阻断时，默认整单阻断；用户移除问题明细后仍需二次确认才能导出剩余明细。

## 10. 输出文件规范

输出必须匹配本次提供的 Amazon MCF 模板：

- 文件类型：`.txt`。
- 分隔符：制表符（TSV）。
- 表头：固定 24 列，顺序与第 9 节一致。
- 编码：UTF-16 Little Endian，带 BOM `FF FE`。
- 换行：CRLF。
- 第一行为表头，后续每行一条订单明细。
- 空字段保留列位置，不得省略制表符。
- 字段值不得包含未清洗的制表符、CR 或 LF。

## 11. 校验与错误处理

### 11.1 阻断错误

出现任一情况时，不允许导出对应订单：

- 文件类型、编码或必要表头不正确。
- 未识别出平台，或文件内容与选择的平台不一致。
- 平台 SKU 为空、未映射或映射已停用。
- Amazon SKU 为空。
- 订单号、Amazon SKU、日期或数量无效。
- 收件人、地址 1、城市、州、邮编、国家或电话缺失/被遮罩。
- 国家不是美国，或州无法标准化。
- 同一 MCF 订单内相同 Amazon SKU 的明细未正确合并。
- 文本清洗后仍包含会破坏 TSV 的控制字符。

### 11.2 警告

以下情况允许用户确认后导出：

- 地址 2、地址 3 或通知邮箱为空。
- TikTok 电话使用了从 `Shipping Information` 提取的建议值。
- 同一订单内多条明细映射到同一 Amazon SKU。
- 用户手工修改了源文件中的收件信息或数量。
- Amazon SKU 为手工输入且未经过主数据校验（仅在 A1 允许时）。

### 11.3 排除项

以下明细不作为错误，但不进入导出：

- 非待发货订单。
- 已取消订单。
- TikTok 非 `Fulfillment by seller` 订单。
- TikTok 扣除退货数量后为 0 的明细。
- 用户主动取消勾选的明细。

## 12. SKU 映射数据要求

建议独立保存平台映射，不修改 Amazon SKU 主数据本身。

| 字段 | 说明 |
| --- | --- |
| Platform | `TEMU` 或 `TIKTOK` |
| PlatformSKU | TEMU `SKU货号` 或 TikTok `Seller SKU` |
| AmazonSKU | 输出到 MCF 的 `MerchantSKU` |
| Status | `active` / `inactive` |
| CreatedBy / UpdatedBy | 创建人、最后修改人 |
| CreatedAt / UpdatedAt | 创建时间、最后修改时间 |

约束：`Platform + PlatformSKU` 唯一；SKU 比较去除首尾空格但保留大小写原值；修改和停用必须留下审计信息。订单文件中的商品名、收件信息不得写入映射表。

## 13. 数据安全与隐私

- 推荐在浏览器本地完成 Excel/CSV 解析、字段转换和 TXT 生成，后端只提供 SKU 映射查询/保存接口。
- 不把源订单文件、生成文件、姓名、电话、邮箱和地址上传到对象存储或数据库。
- 不在前端埋点、后端访问日志或错误日志中记录订单行内容和个人信息。
- 页面刷新、关闭或移除文件时清空内存中的订单数据。
- 仅记录非个人信息审计指标：操作者、平台、明细数量、成功/失败、错误类型、耗时，不记录订单号和地址。
- 若因浏览器兼容性必须改为服务端转换，临时文件应使用随机目录并在请求结束后立即删除，且不得进入备份。

## 14. 性能与兼容性

- 单文件上限：10 MB、20,000 条明细。
- 10,000 条明细解析、映射和生成耗时目标：普通办公电脑 5 秒内。
- 页面转换期间需显示明确进度，避免重复点击。
- 前端表格需分页或虚拟滚动，禁止一次渲染全部明细。
- 表格解析依赖只在进入该工具时懒加载，避免增加主站首屏负担。
- 不调用 AI、OCR、Redis 队列或额外微服务。
- 支持公司当前统一使用的桌面浏览器版本；移动端只允许查看入口并提示使用电脑处理订单文件。

## 15. 埋点与效果指标

### 15.1 事件

- 进入订单转 MCF 页面。
- 文件解析成功/失败（平台、行数、错误类型，不含文件内容）。
- 发现未映射 SKU 数。
- 新增/修改 SKU 映射。
- 生成成功/失败（订单数、明细数、耗时、错误类型）。

### 15.2 上线后观察指标

- 文件解析成功率 ≥ 98%。
- 有效文件的 MCF 生成成功率 ≥ 95%。
- 已维护 SKU 的自动命中率随使用增长，首月目标 ≥ 90%。
- 因工具字段转换导致的 Amazon 模板格式拒绝率为 0。
- 订单个人信息落库和日志泄漏事件为 0。

## 16. 验收标准

### 16.1 模板与格式

- 使用本次 TEMU 样例可以正确识别 32 列和 `SKU货号`，遮罩收件信息被阻断。
- 使用本次 TikTok 样例可以正确识别 63 列中文内容，不出现乱码。
- 输出文件首两个字节为 `FF FE`，采用 UTF-16 LE、制表符和 CRLF。
- 输出表头与 Amazon MCF 模板 24 列逐字、逐序一致。
- Amazon Seller Central 或等价模板校验可以读取生成文件，不出现列错位。

### 16.2 SKU 映射

- 首次出现的平台 SKU 必须人工匹配后才能导出。
- 保存映射后再次上传相同平台 SKU 可以自动命中。
- TEMU 和 TikTok 的同名平台 SKU 不会互相覆盖。
- 平台运营不能修改其他平台映射；管理员可以修改并停用任意映射。
- 修改映射后当前预览立即更新，且保留修改人和时间。

### 16.3 订单规则

- 订单号、SKU 和邮编不会因表格解析变为科学计数法或丢失前导零。
- 日期可从两种来源格式正确转为 `YYYY-MM-DDTHH:mm:ss`。
- TikTok 数量正确扣除退货数量，非卖家履约订单不会进入 MCF。
- 中文/英文州名可以转换为美国两位州代码，未知州被阻断。
- 多明细订单共用订单 ID，`MerchantFulfillmentOrderItemID` 与 `MerchantSKU` 均为 Amazon SKU；相同 SKU 的明细会合并并汇总数量。
- 任一必填地址字段为空、被遮罩或电话明显不完整时整单阻断。

### 16.4 隐私与性能

- 浏览器网络请求中不出现源订单文件或收件人字段，仅发送 SKU 映射查询/保存数据。
- 刷新页面后无法恢复上一份订单内容。
- 日志和埋点中不包含订单号、姓名、电话、邮箱或详细地址。
- 10,000 条明细在目标办公电脑上 5 秒内完成转换，页面不崩溃且可正常筛选错误。

## 17. 上线建议

1. 业务先确认 A1-A7，尤其是 Amazon SKU 主数据来源、订单号前缀和可履约状态。
2. 使用包含完整收件信息的脱敏测试订单，建立 TEMU、TikTok 各一组黄金测试文件。
3. 先向每个平台 1-2 名运营灰度开放，人工对照 Amazon 模板导入结果。
4. 连续验证不少于 3 批真实结构文件且无列错位、无 SKU 错配后，再向全部内部用户开放。
