# STP 文件六面图生成功能设计

## 背景

将产品库的白底图上传改为 STP (STEP) 文件上传，使用 Python + OpenCASCADE (OCCT) 渲染产品六面图，用于 AI 生成图片时作为参考，防止产品变形。

## 需求摘要

1. 用户上传 STP 文件 → Python + OCCT 渲染 6 面图 → 6 张图自动成为产品参考图
2. 6 面图存储于 OSS，URL 记录到数据库 `reference_images` 字段
3. 异步处理，不阻塞用户操作
4. 40 人团队，STP 文件通常 < 50MB

---

## 一、架构设计

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  前端 Vue   │────▶│  Go 后端    │────▶│    OSS      │
└─────────────┘     └─────────────┘     └─────────────┘
                           │                   ▲
                           ▼                   │
                    ┌─────────────┐            │
                    │   Redis     │            │
                    │   队列      │            │
                    └─────────────┘            │
                           │                   │
                           ▼                   │
                    ┌─────────────┐            │
                    │ Python      │────────────┘
                    │ Worker      │
                    │ (OCCT)      │
                    └─────────────┘
```

### 流程

1. 用户在前端上传 STP 文件
2. Go 后端将 STP 文件上传到 OSS
3. Go 后端将任务信息写入 Redis 队列（包含产品ID、OSS路径、用户ID）
4. 前端显示"渲染中"状态
5. Python Worker 从队列拉取任务：
   - 下载 STP 文件
   - 使用 OCCT 渲染 6 面图（正面/背面/左面/右面/顶面/底面）
   - 上传 6 张图到 OSS
   - 更新产品数据库（将 6 张图的 URL + 描述添加到 `reference_images`）
   - 从队列移除任务
6. 前端轮询或 WebSocket 收到完成通知，显示渲染结果

## 四、后端 Go 服务变更

### 4.1 新增 API

#### `POST /product-prompts/:id/stp`

上传 STP 文件并触发渲染。

**请求：**
```
Content-Type: multipart/form-data
file: STP 文件
```

**响应：**
```json
{
  "code": 0,
  "data": {
    "stp_file_url": "oss://products/stp/xxx.stp",
    "render_status": "processing"
  }
}
```

#### `GET /product-prompts/:id/render-status`

查询渲染状态。

**响应：**
```json
{
  "code": 0,
  "data": {
    "render_status": "completed",
    "six_views": [
      {"url": "oss://...", "description": "[六面-正面]"},
      ...
    ]
  }
}
```

### 4.2 Redis 队列设计

**队列名称：** `stp_render_queue`

**任务消息格式：**
```json
{
  "task_id": "uuid",
  "product_id": 123,
  "stp_file_url": "oss://products/stp/xxx.stp",
  "user_id": 1,
  "created_at": "2026-05-25T10:00:00Z"
}
```

**任务状态存储（Redis Hash）：**
```
Key: stp_render_task:{task_id}
Fields:
  - status: pending / processing / completed / failed
  - product_id: 123
  - error_message: ""
  - completed_at: ""
```

### 4.3 任务处理流程（Go 后端）

```
handleStpUpload():
1. 接收 multipart 文件
2. 校验文件类型（.stp / .step）和大小（< 50MB）
3. 上传到 OSS，返回 OSS URL
4. 生成 task_id，写入 Redis Hash（status: pending）
5. 将任务消息写入 Redis List（队列）
6. 更新产品数据库（stp_file_url、render_status: processing）
7. 返回 task_id 和状态

getRenderStatus():
1. 从 Redis Hash 读取任务状态
2. 如果 completed，从数据库读取 six_views
3. 返回渲染状态
```

## 五、Python Worker 实现

### 5.1 技术栈

- Python 3.10+
- open3d 或 OCC (OpenCASCADE Technology)
- Pillow (图像处理)
- oss2 (阿里云 OSS SDK)

### 5.2 项目结构

```
backend/stp-renderer/
├── requirements.txt
├── main.py              # Worker 主入口
├── renderer/
│   ├── __init__.py
│   ├── step_loader.py   # 加载 STP 文件
│   ├── camera.py        # 相机定位（6 个方向）
│   └── image_saver.py   # 渲染和保存
├── oss/
│   ├── __init__.py
│   └── client.py        # OSS 客户端
└── config.py            # 配置
```

### 5.3 渲染逻辑

**相机定位策略：**

| 视角 | 相机位置 | 观察方向 | Up 向量 |
|------|----------|----------|---------|
| 正面 | (0, -d, 0) | +Y | +Z |
| 背面 | (0, +d, 0) | -Y | +Z |
| 左面 | (-d, 0, 0) | +X | +Z |
| 右面 | (+d, 0, 0) | -X | +Z |
| 顶面 | (0, 0, +d) | -Z | +Y |
| 底面 | (0, 0, -d) | +Z | -Y |

**距离 d 计算：** d = max(bbox_size) × 2.5，保证产品完整可见

**渲染设置：**
- 分辨率：1024 × 1024 PNG
- 背景色：纯白色 (#FFFFFF)
- 材质：基础 Lambert 材质，轻微环境光
- 抗锯齿：4x MSAA

### 5.4 任务处理流程

```
worker_main():
1. 连接 Redis，从队列拉取任务（BRPOP）
2. 更新任务状态为 processing
3. 下载 STP 文件到临时目录
4. 调用 render_six_views() 生成 6 张图
5. 上传 6 张图到 OSS
6. 调用 Go API 更新产品 reference_images
7. 更新任务状态为 completed
8. 清理临时文件

render_six_views():
1. 加载 STP 文件为三角网格
2. 计算包围盒，确定相机距离
3. 对 6 个视角分别：
   - 设置相机参数
   - 渲染到帧缓冲
   - 保存为 PNG
4. 返回 6 张图的 OSS URL 列表
```

## 六、错误处理

### 6.1 渲染失败处理

| 错误类型 | 处理方式 |
|----------|----------|
| STP 文件损坏 | 状态设为 failed，记录错误原因，前端提示"文件格式错误" |
| 渲染超时（> 60s） | 任务超时，状态设为 failed，前端提示"渲染超时" |
| OSS 上传失败 | 重试 3 次，失败则状态设为 failed |
| 网络中断 | Worker 重启后从 Redis 恢复任务继续处理 |

### 6.2 重试机制

- 队列任务失败后重试最多 3 次
- 重试间隔：10s、30s、60s（指数退避）
- 3 次失败后状态设为 failed，不再重试
