# STP 白底图生成功能设计

**日期**：2026-06-02
**状态**：已完成设计，待用户审批

## 1. 概述

新增独立页面，允许用户上传 STP 文件，通过 3D 预览选择角度，生成白底图。生成后的白底图可用于后续的场景图生成或 AI 图像生成。

**核心价值**：将 3D CAD 模型（STP）转化为可用于电商/素材的白底产品图，打通 3D 建模与 AI 生图工作流。

## 2. 用户需求

| # | 问题 | 选择 |
|---|------|------|
| 1 | 白底图来源 | **A - 渲染新图**：从 STP 文件实时渲染白底图 |
| 2 | 旋转交互 | **自由旋转 + 实时显示角度/坐标**（非预设按钮） |
| 3 | 生成数量 | **A - 只生成一张**：选择一个角度生成白底图 |
| 4 | 导航位置 | **A - 独立入口**：作为顶级导航项 |
| 5 | 后续操作 | **C - 两者都可以**：场景图生成 + AI 图像生成 |

## 3. 页面设计

### 3.1 布局结构

```
┌────────────────────────────────────────────────────────────────┐
│  STP 白底图                                        [独立导航项] │
├─────────────────────────────┬──────────────────────────────────┤
│                             │                                  │
│                             │  📁 上传 STP 文件                 │
│                             │  （拖拽或点击上传 .stp/.step）    │
│                             │                                  │
│      3D 预览区域             │  ──────────────────────────       │
│   （Three.js 渲染器）        │                                  │
│                             │  旋转角度                         │
│   🧭 坐标系指示器           │  X: 0°  Y: 0°  Z: 0°            │
│   （X/Y/Z 轴可视化）         │  （拖拽模型时实时更新）          │
│                             │                                  │
│                             │  [     生成白底图     ]           │
│                             │                                  │
├─────────────────────────────┴──────────────────────────────────┤
│  生成结果区（生成完成后显示）                                   │
│  ┌─────────┐  [下载]  [去生成场景图]  [去 AI 图像生成]        │
│  │ 白底图  │                                                   │
│  │  预览   │                                                   │
│  └─────────┘                                                   │
└────────────────────────────────────────────────────────────────┘
```

**说明**：
- **左侧 60%**：Three.js 3D 渲染区域，支持鼠标拖拽旋转、滚轮缩放
- **右侧 40%**：操作面板，包含上传、角度显示、生成按钮
- **底部**：生成结果区，生成完成后显示预览和后续操作

### 3.2 3D 预览交互

- **旋转**：鼠标左键拖拽（OrbitControls）
- **缩放**：滚轮
- **平移**：鼠标右键拖拽
- **角度显示**：实时显示 X/Y/Z 轴旋转角度（欧拉角），拖拽时实时更新
- **坐标系指示器**：显示 X/Y/Z 轴方向（参考 C4D 的坐标轴显示）

### 3.3 角度显示区域

显示当前模型的旋转状态：
```
X: 45°   Y: 30°   Z: 0°
```
- 角度单位：度（°）
- 拖拽时实时更新
- 角度范围：0° ~ 360°

## 4. 功能流程

### 4.1 主流程

```
1. 用户进入页面
2. 上传 STP 文件（拖拽或点击）
3. Three.js 加载模型 → 显示 3D 预览
4. 用户拖拽旋转模型，观察角度显示
5. 角度满意后，点击"生成白底图"
6. 前端调用后端 API，传递角度参数
7. 后端调用 Python Worker 渲染单张白底图
8. 渲染结果上传 OSS，返回 URL
9. 前端显示白底图预览
10. 用户可选择：
    - 下载白底图
    - 跳转到"场景图生成"（传递图片 URL）
    - 跳转到"AI 图像生成"（传递图片 URL）
```

### 4.2 后端处理流程

```
请求 → Go API → Redis 队列 → Python Worker → 渲染 → OSS → 返回 URL
```

## 5. API 设计

### 5.1 前端 → 后端

**POST /api/stp-render/single**

请求：
```json
{
  "stp_file_url": "oss://bucket/path/model.stp",
  "camera_angle": {
    "azimuth": 45,    // 方位角（度）
    "elevation": 30,  // 仰角（度）
    "distance": 1.0   // 距离因子
  },
  "resolution": 1024
}
```

响应：
```json
{
  "task_id": "abc123",
  "status": "processing"
}
```

**GET /api/stp-render/single/:task_id**

响应：
```json
{
  "task_id": "abc123",
  "status": "completed",
  "image_url": "https://cdn.xxx.com/xxx.png",
  "created_at": "2026-06-02T10:00:00Z"
}
```

### 5.2 文件上传流程

**POST /api/upload/stp**

请求：multipart/form-data，包含 .stp 或 .step 文件

响应：
```json
{
  "url": "oss://bucket/path/uuid-model.stp"
}
```

### 5.3 后续操作跳转

白底图生成后，跳转到其他页面时，通过 URL 参数传递图片 URL：

```
/scene-generator?product_image=https://cdn.xxx.com/xxx.png
/generate?reference_image=https://cdn.xxx.com/xxx.png
```

## 10. 性能要求（重要约束）

**项目背景**：约 40 个用户同时使用，需要保证流畅和低内存占用。

### 10.1 前端性能要求

| 指标 | 要求 | 说明 |
|------|------|------|
| 首次加载 | < 2s | 3D 查看器懒加载，不阻塞页面 |
| 模型加载 | < 3s | 对于 10MB 以下的 STP 文件 |
| 旋转帧率 | ≥ 30 FPS | 拖拽旋转时保持流畅 |
| 内存占用 | < 200MB | 浏览器中 Three.js 场景总内存 |
| 卸载清理 | 必须 | 页面切换时完全释放 WebGL 资源 |

**前端性能优化策略**：

1. **模型简化**
   - 加载时自动简化 mesh（减少三角形数量）
   - 使用 BufferGeometry 替代 Geometry
   - 合并重复的几何体

2. **渲染优化**
   - 使用 requestAnimationFrame 渲染循环
   - 不渲染时暂停动画循环
   - 使用适当的材质（MeshStandardMaterial 而非复杂 shader）

3. **内存管理**
   - 页面卸载时完全 dispose 所有 Three.js 对象（geometry, material, texture, renderer）
   - 不在内存中缓存多个模型
   - 使用弱引用处理临时对象

4. **懒加载**
   - Three.js 相关代码异步加载
   - OrbitControls 按需加载
   - 不在首屏加载时初始化渲染器（等用户上传文件后再初始化）

### 10.2 后端性能要求

| 指标 | 要求 | 说明 |
|------|------|------|
| 渲染超时 | 60s | 超过则任务失败 |
| 并发限制 | 2-3 个 | 同时渲染的任务数 |
| 内存限制 | < 500MB | 每个 Worker 进程 |
| 临时文件清理 | 必须 | 渲染完成后立即清理 |

**后端性能优化策略**：

1. **复用现有管道**
   - 复用 `stp-render` 的 Python Worker
   - 不新增额外的渲染进程

2. **并发控制**
   - 通过 Redis 队列控制并发数
   - 避免多用户同时渲染导致服务器压力过大

3. **资源清理**
   - 渲染完成后立即删除临时 STP 文件
   - 及时释放 Open3D/OCC 对象
