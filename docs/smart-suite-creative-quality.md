# 智能套图：生图前创意验收

智能套图在产品事实、买家问题、创意方向、文案和逐图脚本完成后，可以调用 `evaluate-suite-creative` 记录整套方案的风险和建议。它不再是生图阻断门；生图只依赖后端确定性的事实绑定、文案、布局结构和必填字段校验。这样模型审核出现审美偏好或不确定判断时，不会让整套任务停在验收阶段。

## 验收范围

审核区分 `blocker` 与 `suggestion`：无依据的明确主张、编造单位、明确的适配演示、产品身份错误和不可能动作记录为阻断风险；普通吊柜背景、柜边文字对齐、构图偏好及仅有“可能暗示”的推测记录为建议。两类结果都保存在 `creative_review`，但模型结论不决定是否生图；真正阻断只由后端确定性校验决定。

- narrative：图片主题是否重复、信息顺序是否合理、桌面与手机 A+ 的表达是否一致。
- copy：文案是否自然、是否表达有依据的购买价值、规格是否有完整单位。
- visual：镜头和构图是否服务于卖点，动作、接触和产品结构是否合理。
- facts：主张是否有产品事实支持；缺失单位不能靠猜测补齐。

验收返回四项具体结论，以及定位到图片类型和序号的问题。若发现明确风险，只返工这些图片的创意字段，保留原有事实分配、产品身份和安装位置；创意阶段最多执行一次完整修复，同一张图允许一次语义修复和一次结构格式纠正。审核调用失败或修复失败会记录在任务日志中，但不会阻止已通过后端确定性校验的方案进入生图。传输错误和响应格式错误另有有界重试。

事实绑定保持不变；验收发现 `facts`/`narrative` 问题时也先尝试有界局部纠正，不再仅因问题分类就直接停止任务。可删除无依据的单位、适配承诺和相关场景暗示，但不得补造事实。缺少单位时省略整个数值，使用中性的产品轮廓表达。文案批量生成不包含隐藏的整批 repair，只对缺失或不合规模块做一次定向补齐。

通过结果绑定输入指纹；方案、语言、市场、风格要求或参考图地址变化后，旧结果失效。验收记录保存在现有任务快照的 `creative_review` 中，无需新增数据库表。

## 出图后重做

现有图片审核与生图前方案验收是两个不同阶段。出图后仍只审核一次；重做先基于原完整提示词改写执行字段，再使用真实产品参考重新生成，不引用失败的生成图，也不再次审核重做结果。提示词改写失败会携带具体错误重试一次。

不新增主图，不审核画布尺寸。不会自动启用额外收费的样图或多候选生图。

## 运维与验证

新增 Agent 使用 `getSmartSuiteAgentModel("creative_review")` 的模型解析逻辑。调用日志记录请求提示词、响应、耗时、用量和调用错误；生图日志记录实际提示词与模型参数。内置 Skill 随后端编译，部署新后端后才会影响线上执行，历史图片不会自动改变。

自动测试验证调度门禁、输入变化失效、定向返工、事实保护、格式错误恢复和返工次数上限。它们不证明图片审美已达到参考文章效果；上线验收仍需使用同一产品资料、真实参考图和固定模型实际生成，对比文案、产品真实性和整套视觉表现。

## 模型调用层级

编排器按后端依赖顺序直接选择下一个 Agent，不再每一轮额外调用路由对话模型；编排器也不再在 Agent 已经失败后再套一层通用重试。每个 Agent 只保留自己的结构校验和有界修复。这样减少了“路由模型 + 执行模型 + 修复模型 + 通用重试”的叠加调用，也让失败日志对应到真正失败的阶段。

一次正常任务仍会分别调用事实分析、买家问题、风格、创意导演、文案、画面规划、创意验收和生图阶段；它们是不同职责，不会像 Codex 单个执行上下文那样天然合并。异常时会增加该阶段的修复调用，但受各 Agent 的上限约束。当前代码测试覆盖了调用选择和重试边界；线上调用次数需要从 `UsageLog` 按 `source` 汇总确认。

当前仍采用已有逐图事实分配及单候选生成机制；本次未实现视觉样图选方向、多候选筛选或独立图文合成。
